# Batch 0.2: LLM Adapter

## Built

- Provider-neutral `LLMProvider` interface with validated chat request and response types.
- OpenAI-compatible provider using Bun's native `fetch`.
- Zod validation for requests, provider responses, and token usage.
- Retries for rate limits and server failures, with configurable retry count and delay.
- Demo command that sends a prompt and prints the response plus total token usage.
- Mocked tests for successful responses, token mapping, transient retries, and non-transient failures.

## Decisions

- The first adapter targets the OpenAI-compatible `/chat/completions` protocol instead of adding a provider SDK. Native `fetch` keeps the package small and avoids Node-specific client behavior on Bun.
- Provider-reported usage is returned directly as normalized `TokenUsage`; local token estimation is deferred until the gateway needs preflight budget checks.
- The transport is injectable so tests never require credentials or network access.

## Run

```sh
OPENAI_API_KEY=... bun run --cwd packages/llm prompt -- "Say hello in one sentence"
```

Set `OPENAI_BASE_URL` for another OpenAI-compatible endpoint and `OPENAI_MODEL` to select its model.

## Learned

An interface isolates the agent from provider-specific wire formats. Runtime schemas are still needed at the boundary because TypeScript types disappear before the provider response reaches the application.
