# Batch 2.1: Sandbox Image and Docker Client

## Built

- Bun-native Docker Engine client using `fetch` over `/var/run/docker.sock`.
- Container lifecycle methods: create, start, stop, and remove.
- Mocked lifecycle and API-error tests without requiring a Docker daemon.
- Minimal `oven/bun:1.4.4-alpine` sandbox image with `/workspace` and the existing non-root `bun` user.
- Hardened create defaults: no network, read-only root filesystem, all capabilities dropped, and `no-new-privileges`.

## Decisions

- No Docker SDK dependency was added. Bun 1.4.4 declares and supports `fetch` with a `unix` socket option, so the client uses that native transport.
- The Docker request function is injectable, making API behavior testable without mounting the host Docker socket.
- The official Bun base image already owns UID 1000, so the image uses its existing `bun` user rather than creating a conflicting user.

## Verification

```sh
bun run --cwd packages/sandbox test
bun run --cwd packages/sandbox typecheck
docker build -t wildfire-sandbox:test infra/docker/sandbox
docker run --rm wildfire-sandbox:test id -u
```

The image build check returns UID `1000`.
