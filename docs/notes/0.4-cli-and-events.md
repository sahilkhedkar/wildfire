# Batch 0.4: CLI and Event Logging

## Built

- `wildfire run "task" --dir ./folder` CLI entrypoint.
- JSONL trace output for run start, LLM requests and responses, tool calls and results, completion, and errors.
- Versioned trace events with monotonically increasing sequence numbers and timestamps.
- Agent event hooks that keep orchestration independent from the trace sink.
- End-to-end CLI test proving a scripted provider can create a file and produce ordered events.

## Run

```sh
OPENAI_API_KEY=... bun run --cwd apps/cli src/index.ts run "Create hello.ts" --dir ./workspace
```

Each output line is one JSON event. The CLI uses `OPENAI_MODEL` and `OPENAI_BASE_URL` when present, defaulting to `gpt-4o-mini` and OpenAI's API URL.

## Decisions

- JSONL is the initial trace transport because it is streamable, shell-friendly, and easy to persist or pipe into later tooling.
- Trace recording is injected through callbacks rather than embedded in the agent loop, allowing database and live-stream sinks later.
- Sequence numbers are assigned by the recorder, making ordering independent of event producers.

## Learned

The CLI is a thin composition root: it parses user input, chooses the provider, creates the trace sink, and starts the agent. Keeping it thin makes the same agent runnable from workers and tests without process-level assumptions.
