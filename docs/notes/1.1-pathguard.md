# Batch 1.1: Path Guard Interface and Normalization

## Built

- `PathGuard` interface returning explicit `allowed` or `denied` decisions.
- TypeScript implementation with `read`, `write`, `list`, `delete`, and `execute` operation kinds.
- Root normalization with absolute path resolution.
- Normalization for duplicate separators, `.`, `..`, trailing separators, and absolute paths.
- Denial for null bytes, unknown operations, and paths outside the workspace.

## Decisions

- Absolute paths are allowed only when their normalized target is within the configured workspace root.
- The decision includes the normalized resolved path so callers do not re-resolve the request independently.
- The guard is lexical in this batch. Symlink targets, encoded paths, Unicode lookalikes, and TOCTOU behavior are intentionally deferred to Batch 1.2 and later sandbox hardening.
- Batch 1.2 adds filesystem-aware symlink checks and encoded traversal checks. TOCTOU behavior remains a later sandbox and descriptor-level concern.

## Learned

Containment must compare a normalized candidate against the normalized root, not use string prefixes. Otherwise a workspace such as `/workspace` could accidentally authorize a sibling such as `/workspace-other`.
