# Batch 1.4: Wire Path Guard Into Tools

## Built

- Agent workspace tools now depend on the shared `PathGuard` interface.
- `read_file`, `write_file`, and `list_dir` call the guard with their operation kind before filesystem access.
- The TypeScript Path Guard is the default implementation, while tests can inject a recording or alternate implementation.
- Tool tests verify all three operations invoke the guard.

## Decisions

- Guard injection happens at `createWorkspaceTools`, keeping the agent loop independent from a specific guard implementation.
- Denied guard decisions become tool error results, allowing the model to observe a blocked operation without touching the filesystem.
- The guard returns the resolved path used by the tool, avoiding a second lexical path resolution in the tool layer.

## Honest limitation

The current tools still call filesystem APIs by path after the guard returns. This closes the missing-guard gap but does not eliminate TOCTOU races; descriptor-safe operations remain a later hardening step.
